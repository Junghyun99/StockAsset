# 코드 스타일 규칙

## Python
- Python 3.10 기준으로 작성
- 클래스 기반 설계: 각 컴포넌트는 클래스로 구현
- 타입 힌트 사용 권장 (core/models.py 참고)
- 한글 주석 허용 (프로젝트 전반에서 한글 주석 사용 중)

## 네이밍
- 클래스: PascalCase (예: RegimeAnalyzer, VolatilityTargeter)
- 함수/변수: snake_case (예: calculate_exposure, market_data)
- 상수: UPPER_SNAKE_CASE (예: ASSET_GROUPS, IS_LIVE_TRADING)

## 모듈 구조
- core/: 외부 의존성 없는 순수 도메인 로직
- infra/: 외부 API, 파일 I/O 등 인프라 계층
- utils/: 공통 유틸리티 (로깅, 계산)
- backtest/: 백테스트 전용 코드

## 클래스 적정 사이즈 (클린 아키텍처 기준)

### 수치 기준
| 항목 | 권장 | 경고 |
|------|------|------|
| 클래스 라인 수 | 100~200줄 | 300줄 초과 |
| 메서드 수 | 5~10개 | 15개 초과 |
| 메서드 라인 수 | 10~20줄 | 30줄 초과 |
| 생성자 파라미터(의존성) 수 | 3~4개 | 5개 초과 |

### 레이어별 기준
- core/: 100~200줄 (순수 로직, 변경 이유 최소화)
- infra/: 150~250줄 (외부 API별로 클래스 분리)
- backtest/: 200~300줄 (재사용 프레임워크)
- utils/: 50~100줄 (단순 유틸)

### 핵심 원칙: SRP (단일 책임 원칙)
클래스가 변경되는 이유는 하나여야 한다.

### 클래스 분리 신호
- 클래스 이름에 `And`, `Manager`, `Handler`가 포함될 때
- 메서드들이 서로 다른 필드만 사용할 때
- 테스트 작성 시 mock이 5개 이상 필요할 때
- 새 기능 추가 시 관련 없는 메서드가 눈에 띌 때
