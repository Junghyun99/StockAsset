# TqqqVrEngine — 기본 VR + 매일 변동성 비중 제한

최종 연구 후보 `basic_p20_c50_g10_w1`을 신규 엔진으로 구현한다.
기존 계좌 설정은 변경하지 않으며, 전용 TQQQ/현금 계좌에서 선택하는 엔진이다.

## 재사용 구조

- `TradingEngine`: 수집 → 지표 → 포트폴리오 → 주문 → 상태 확정 → 기록 공통 흐름.
- `StrategyDataSpec`: QQQ 데이터 선언, 기존 IDataProvider 사용.
- `StrategyDecision`, `OrderBatchResult.actual_executions`: 주문 결정과 실제 체결 분리.
- `restore_strategy_state` / `commit_strategy_state`: 기존 계좌별 JsonRepository 저장.
- `DecisionFactor`: V, 잔여 예산, 비중 상한과 체결 확인 상태를 기존 대시보드에 제공.
- 레지스트리와 브로커는 기존 구현 사용. TQQQ의 NAS 거래소 매핑 추가.

일반 Rebalancer는 목표 비중을 채우고 회전율 임계치를 적용하므로 사용하지 않는다.
VR은 하단 신호가 있을 때만 매수하며, 비중 상한 완화 자체는 매수 신호가 아니다.
기존 VolatilityTargeter에는 국면별 강제 축소와 최소 노출이 있어 이번 공식을 대체하지 않는다.
21일 공통 지표도 그대로 재사용하면 규칙이 바뀌므로 QQQ 종가(`Close`)로 20일 표본 변동성을 별도 계산한다.

사용자 결정에 따라 변동성 입력은 기존 엔진과 동일한 `Close`로 통일한다. 캐시에 `Adj Close`를 추가할 필요가 없다. 이전 연구는 조정종가를 사용했으므로 기존 성과 수치는 Close 기반 변경 후 재검증해야 한다.

## 고정 규칙

| 항목 | 값 |
|---|---|
| 자산 | TQQQ + 현금 Pool |
| 초기 V / 매수 예산 | 최초 계좌 현금 × 80% (비용 포함) |
| 사이클 | 시작일부터 7 달력일, 첫 관측 거래일에 갱신 |
| V 갱신 | 직전 V + 추가 매수 가능액 / 10 |
| 사이클 매수 예산 | 직전 저장 Pool × 50% |
| 밴드 | 0.85V / 1.15V |
| 변동성 | QQQ 전일 이전까지 21개 종가(`Close`) → 20개 수익률 표본 표준편차 × √252 |
| TQQQ 상한 | min(1, 0.30 / (3 × 변동성)) |
| 판단 | 매 거래일, 매도 우선, 매도일 매수 금지 |
| 수량 | 정수 주식 |
| 기본 예상 편도 비용 | 0.0025 = 0.25% |

새 사이클 첫 거래일의 주문 전 평가액으로 상한 여유액을 계산한다.
추가 매수 가능액은 `max(0, min(직전 저장 Pool, 비중 상한 × 계좌 평가액 − TQQQ 평가액))`이다.
예를 들어 직전 Pool이 45이고 계좌 평가액이 100, TQQQ가 55, 상한이 60%라면 V는 0.5 증가하고 사이클 예산은 22.5다.
기존 상태로 재개하면 저장된 V를 출발점으로 다음 사이클부터 적용한다.

`fee_rate` 생성자 인자로 0.001(0.10%) 등 변경 가능하다. 이는 주문 크기 계산용 예상 비용이며
실제 잔여 예산 차감은 체결 금액 + 보고된 실제 수수료다. 기존 MockBroker는 수수료 0.25%와
슬리피지 0.10%를 실제 체결에 반영한다. 엔진에 슬리피지 추정을 추가하지 않으며, 비용으로 인한
사이클 예산의 소폭 초과와 비중 상한 오차는 허용한다. 예산 초과 시 추가 매수 가능액은 0이다.
브로커의 현재 현금 98% 및 예상 가격 101% 안전마진은 유지하며, 사이클 예산 설정과는 별개다.
실거래 수수료/슬리피지와 항상 같다는 의미는 아니다. 계좌 YAML에 임의 fee_rate 필드를 추가해도
현재 공통 계좌 로더는 이를 엔진 인자로 전달하지 않는다.

- 초기 매수에도 알려진 비중 상한을 적용한다. 상한이 80%보다 낮으면 최초 배분도 낮아진다.
  연구 자료의 첫날 상한 100% 가정을 임의의 실거래 시작일에 강제하지 않는다.
- 매도는 `max(VR 상단 복원 수량, 비용 차감 후 상한 충족 수량)` 하나의 주문이다.
- 매수는 `min(하단 복원 필요량, Pool 허용량, 사이클 잔여 예산 허용량, 상한 허용량)`이다.
- 매도 대금과 이자/배당은 Pool이 되지만 현재 사이클 예산을 재충전하지 않는다.
- 새 사이클의 예산은 재계산하며, 미사용 예산을 더하지 않는다.
- 0변동성은 상한 100%. 결측/비정상 Close는 거래 중단이며 Adj Close로 대체하지 않는다.
- 초기 포지션은 별도 매수이며 사이클 예산을 소모하지 않는다. 실제 초기 체결 뒤 남은 Pool로 첫 예산을 만든다.

## 실행 날짜와 체결

기존 템플릿에 공통 `cycle_date` 실행일 컨텍스트를 추가했다. 다른 엔진의 기본 KST 날짜는 유지하고
본 엔진의 실시간 실행일만 America/New_York를 사용한다. `sim_date`는 항상 우선한다.
QQQ는 실행일보다 날짜가 작은 행만 사용하므로 당일 미완성 일봉은 제외한다.
공통 MarketData의 21일 변동성/국면은 본 엔진 주문에 쓰지 않는다.

VR 가격 판단은 기존 브로커가 제공하는 실행 시점 현재가를 사용하고 즉시 기존 브로커에 주문한다.
미국 거래일에 하루 한 번 스케줄링해야 하며, 이 PR은 계좌·실거래 스케줄을 활성화하지 않는다.
한 거래일을 평가하면 재실행/재시작에도 중복 주문을 내지 않는다. 명시적 거절도 같은 날 자동 재시도하지 않는다.

## 상태와 체결 확인

`strategy_state.json`의 `tqqq_vr` 키에 `anchor, cycle, value, budget, spent, last_date,
closing_pool, initialized, reconciliation_required`를 저장한다.

- 예상 주문만으로 spent를 차감하지 않는다. FILLED/PARTIAL의 보고된 수량·가격·비용만 반영한다.
- ORDERED/PARTIAL/ERROR 결과는 미확인 잔여 주문 가능성이 있어 `reconciliation_required=true`로
  저장하고 이후 거래를 막는다. 공통 주문 경고 기록도 유지된다.
- MockBroker/BacktestBroker에서 현금·보유량에 맞춰 줄인 수량이 전부 체결된 경우는
  FILLED로 처리한다. 원래 요청과 실제 체결 수량 및 조정 사유는 보존하며 확인 대기하지 않는다.
  수량 차이만으로 PARTIAL을 추정하지 않고, 명시적인 PARTIAL 상태는 그대로 유지한다.
- 초기 부분체결도 실제 체결을 초기 배분으로 기록하되, 동일하게 확인 대기한다.
- 운영자가 브로커 체결·미체결 내역을 확인하고 잔여 주문을 처리한 뒤, 미반영 체결의 예산 소비와
  Pool을 맞추고 플래그를 해제해야 한다. 플래그만 지우면 안 된다. 자동 사후 정산 기능은 이 PR 범위 밖이다.
- 주문 제출과 파일 저장 사이의 프로세스 장애는 기존 공통 실행 구조의 한계다. 장애 후에는 브로커와
  상태를 대조한 후 재개한다. 다중 프로세스 동시 실행은 지원하지 않는다.
- 시작 상태 없이 기존 TQQQ를 보유한 경우 초기 설정을 요구하며 임의로 V를 추정하지 않는다.
- 공통 베이스는 다른 엔진의 잔여 종목을 자동 청산한다. 기존 투자 계좌의 엔진을 바꾸는 방식으로
  활성화하지 말고 전용 계좌/정합한 상태에서 사용한다.
- 며칠 실행을 놓치면 마지막 저장 Pool로 한 번 갱신한다. 누락된 주간 복리를 소급 합성하지 않는다.
  일별 실행이 전제이며 입출금/수동 매매 후 V 조정은 자동화하지 않는다.

## Pool 이자와 백테스트 범위

실거래 Pool은 브로커 실제 현금이며 엔진이 가상 이자를 적립하지 않는다. 현금 이자가 없는 계좌라면
연구의 무위험수익률을 얻을 수 없다. 이 엔진은 SHV를 대신 매수하지 않는다.
`backtest=True`로 등록하여 자동 전체 비교 목록에 포함한다. TQQQ는 엔진 자산 그룹에서,
QQQ는 해외 벤치마크에서 다운로드 대상에 포함되며, 변동성은 전일 이전 Close를 사용한다.
현재 비교 기준은 현금 이자 0%, 샤프 무위험수익률 0%, 브로커 수수료 0.25%와 슬리피지 0.10%다.
매 거래일 판단을 위해 비교 러너의 execution_interval은 1로 실행한다.
현재 비교 러너의 Pool 이자·가격 체결 조건은 기존 연구 스크립트와 같지 않다.
기존 CAGR 30.95%, MDD -42.39%,
샤프 0.937(편도0.25%)를 저장소 러너가 이미 재현했다는 주장은 하지 않는다.

최초 배분 상한, 실제 현재가 체결, 실제 현금 이자, 초기 부분체결과 실행 누락은 연구의 이상화와
다를 수 있으므로 실거래 활성화 전 동일 엔진 기반 재검증이 필요하다.

## 계좌 설정 예시 (실행 비활성)

```yaml
- id: tqqq_vr_paper
  market_type: overseas
  is_live: false
  is_active: false
  engine: TqqqVrEngine
  kis_env_prefix: TQQQ_VR_PAPER
```

기존 `accounts.yaml`을 자동 변경하지 않는다. 비활성 계좌는 기존 공통 흐름대로 조회만 한다.

## 5%p 매도 데드밴드 변형

비교 백테스트에 등록된 `TqqqVrDeadbandEngine`은 동일한 QQQ 20일 변동성 상한을 사용한다. 현재 TQQQ 비중이 상한을 5%p 이내로 초과하면 상한 매도를 유예하고, 5%p를 넘으면 원래 상한까지 매도한다. VR 상단 밴드 매도는 매일 독립적으로 판정하며 매수 여유와 주간 V 갱신에는 원래 상한을 적용한다. 상태 키는 `tqqq_vr_deadband`다.

## 22.5% 목표 · 매수 2%p 데드밴드

비교 백테스트 엔진 `TqqqVrBuyDeadbandEngine`은 전 거래일까지의 QQQ 20일 연환산 변동성으로 상한 `min(1, 0.225 / (3 × 변동성))`을 계산한다. 최초 배분 후 VR 하단 매수 조건을 충족해도 상한과 현재 TQQQ 비중 차이가 2%p 미만이면 매수를 유예한다. 정확히 2%p부터 기존 예산과 상한 내에서 매수한다. 상한 초과 매도와 VR 상단 매도는 즉시 판단한다. 상태 키는 `tqqq_vr_buy_deadband`다. 연구에서 가정한 예수금 이자는 브로커의 현금 운용 조건에 따르며 엔진이 별도로 적립하지 않는다.
